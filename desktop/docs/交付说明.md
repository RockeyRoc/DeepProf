## 一、这是什么

Electron + React（+ PixiJS）写的**桌面桌宠**，是 DeepProf 交互层（DESIGNv0.4.1 §4.1）第一个能跑起来的模块，对应 §16.4 张钧翔的任务书。

一句话职责：**把 Runtime 吐出的事件流，翻译成一个看得见、听得着、能摸的小人。**

### 定位（不吹牛的部分）

- 计划书 §3.3 写明：桌宠 / 语音是「**核心学习流程完成后的交互完善**」。
  因此**本轮不声称桌宠带来任何学习提升**，它的价值是把「事件 → 表现」这条链路先跑通、可视化。
- 本模块**不产生**任何教学内容、不做检索、不调模型。界面上所有"回复"都来自主进程里的 **Mock**
  （`desktop/src/main/index.js` 的 `SCRIPT` 常量），**不是真回答**；末尾那句「以上是 Mock 演示数据」是刻意放的。
- 当前处于 §16.8 的**阶段 02「独立最小模块」**：桌面端能独立跑通；阶段 02 集成门槛要求的三份文档在 `desktop/docs/` 下。

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 开发模式，改 renderer 代码热更新；改 main / preload 需重启 |
| `npm run build` | 编译到 `out/`（main / preload / renderer 三份产物） |
| `npm run start` | **直接跑 `out/` 里的旧产物，不会重新编译** |

**启动后应该看到**：屏幕**右下角**出现一个小人（**220×420** 无边框透明置顶窗口，只有角色、没有面板）；
终端打印 `[桌宠] 窗口已显示 @ (x, y) 220x420`、`[桌宠] 渲染诊断: {...}`、`[桌宠] 快捷键 ... ✅/❌`。
终端里刷的 `[窗口诊断] resize` / `[气泡诊断]` 是**临时诊断日志**，不是故障。

**关掉那个黑窗口 = 退出桌宠**（它是 `npm run dev` 的宿主进程）。
**点小人窗口的关闭按钮 ≠ 退出，只是隐藏** —— 这是刻意的，避免误关丢桌宠。

## 三、有哪些操作

| 操作 | 效果 | 备注 |
| --- | --- | --- |
| **左键单击** | 有反应（点头 / 弹跳 / 台词） | 点在上半部居中的「头」区算**摸头**，好感度加成更高 |
| **左键双击** | 展开 / 收起**对话面板**（窗口 220×420 ↔ 380×620） | 面板已开着时再双击**不会**把窗口往上顶（踩过这个坑，已修） |
| **按住拖动** | 把小人拖到任意位置，期间自动漫游暂停 | 不用 `-webkit-app-region: drag`，因为那样就收不到 click 了 |
| **滚轮** | 缩放角色大小 | 乘在自动适配缩放之上；窗口尺寸变化时自适应 |
| **右键菜单** | 打开 / 收起对话 · 随便走走 · 回到原位 · 让它自己走（漫游开关）· 窗口置顶 · 恢复默认大小 · 换成分层走路 / 换成逐帧动作 · 点击穿透 · 退出 | 菜单项以 `src/renderer/src/App.jsx` 当前实现为准。「Live2D 本轮不提供（当前使用逐帧 PNG 方案）」那一项点了只会弹一段说明 —— 本轮范围决定，见 §五 |
| **托盘图标右键** | **第一项「退出」** / 显示·隐藏 / 把小人叫回来（归位）/ 自动溜达（**默认关闭**） | 托盘是**任何状态下都能退出**的兜底出口 |
| **快捷键 `Ctrl+Alt+Shift+X`** | **强制退出** | 全局快捷键，注册失败时终端会打 ❌ |
| **快捷键 `Ctrl+Alt+Shift+D`** | **归位**（把小人叫回屏幕底边） | 小人找不到时的救命键 |

**退出方式**：托盘第一项「退出」/ 右键菜单「退出」/ `Ctrl+Alt+Shift+X` / 关掉黑窗口。

> **找不回小人时**：按 `Ctrl+Alt+Shift+D`，或托盘右键「把小人叫回来（归位）」。
> 注意：手动开了「点击穿透」后**在界面上关不掉**（已知缺陷，见 `desktop/README.md` §六）。

## 九、必须知道的三个「坑」（别被问到答不上来）

### 9.1 性能数据包**不是当前构建**的

`性能数据/README.md` 里的数字对应 **12:45 的构建**，而 `out/` 之后被重建了多次。
已在文件顶部加了醒目 banner，但**评审只要跑一次 `npm run build` 就会发现体积对不上**。

- 报告的 `out/` **6.87 MB** → 现在 **15 MB**
- 「扣掉 Live2D 后 2.97 MB」→ 现在没有 Live2D 了，这个数不成立
- 主打数字 **478.6 ms「双击 .bat 的体感」是错的** —— `.bat` 跑的是 `npm run dev`，真实体感是 **1394.7 ms**

**重测前请先冻结代码**，否则数字永远追不上。详见该文件 §6。

### 9.2 眨眼帧是**合成**出来的，不是原图（2026-09-20 重写）

组长给的两张（睁眼张嘴 / 闭眼张嘴）是**两次独立生成**，不是同一张图改眼睛：

- 全身 **21.5%** 的像素不同；
- 整体平移**解释不了** —— 挪 4px 只消掉 14% 的差异；
- 两张的轮廓框**底部差 9px**。

**后果**：直接把两张丢进流水线当 `blink_0` / `blink_1`，**切帧时整个角色会抖一下**
（头发丝、裙褶、描边、脚全在动）—— 那不是眨眼，是"整个人抖了一下"。

**做法**：交付里的 `blink_1.png` 是**合成**的 —— 拿 `blink_0` 当底，
**只把闭眼图的眼部区域贴上去**（`tools/素材流水线/眨眼合成.py`，随交付走）。
这样 `blink_1` 的身体像素与 `blink_0` **完全一致**，抖动**为零**。

**验收依据**：120 张窗口连拍 @120ms，靠**数蓝眼珠像素**定位闭眼帧（t38 / t86），
间隔 **5.76 秒**随机触发，闭眼约 110ms，**无接缝**。

⚠️ **换素材时别把新闭眼图直接丢进流水线** —— 先跑那个脚本。
⚠️ 另外：**别用"整体像素差异"去找眨眼帧** —— 那样找出来的是 **1px 的 bob 弹跳**，
它的差异（5.9）比闭眼（0.8）还大，会得出错误结论。

> **历史**：09-19 那版旧角色踩的是**另一个**坑 —— 即梦整张重生成把角色**画宽**了
> （`blink_1` 宽 12%、`talk_1` 宽 5%），靠**横向压缩**修的。
> 那套帧已随换角色**停用**，但这条教训还在：**即梦重生成 ≠ 同一张图**。
