## 〇、为什么要做原创角色

现成的「鲸鱼娘 / DeepSeek 娘」授权是 **CC BY-NC-SA 4.0**：

- **NC** —— 禁止商用。我们计划书里写了「成果转化」「申请软件著作权」，属于商业目的，踩线
- **SA** —— 衍生作品必须同协议共享。一旦采用，转化路径直接堵死
- 软著登记要求**独创性**，用他人 NC 素材登记可能被异议

**结论：形象必须原创，著作权 100% 归团队。**

> 保留「蓝鲸少女 + Q 版」的方向没问题，但要**换掉具体设计**。

## 一、角色设定

### 1.1 基本设定

| 项 | 设定 |
| --- | --- |
| 身份 | 大学生的**学伴**（不是女仆） |
| 性格 | 认真但不古板，会追问、会提醒、会陪你熬夜 |
| 口头禅 | 待定（建议由团队共创） |
| 名字 | **待团队定**（注意：不要含「DeepSeek」等第三方商标） |

### 1.2 造型规格（**这是和参考角色拉开距离的关键**）

| 部位 | 规格 | 与参考角色的区别 |
| --- | --- | --- |
| **服装** | **学院风**：白衬衫 + 蓝色针织开衫 + 深蓝百褶**短裙** | ⚠️ **不用女仆装** —— 女仆装是参考角色最标志性的特征 |
| **发型** | **双马尾**（或侧马尾），发梢微卷 | ⚠️ **不用齐刘海长直发** |
| 发色 | 深蓝 `#2E4A7D` → 浅蓝 `#6FB3E0` 渐变 | 蓝调保留，具体色值不同 |
| 眼睛 | 大眼，亮蓝 `#3D8BD4` | — |
| **鲸鳍耳** | 耳侧一对鲸鱼胸鳍（深蓝主体 + 白边） | ✅ **保留** —— 这是「鲸」的核心识别点 |
| **尾巴** | 小鲸鱼尾，**短，垂在身后，不拖地** | ⚠️ 必须有 —— 长了会挡住腿，影响走路动画 |
| 腿 | **裸露可见** + **过膝袜** + 深蓝小皮鞋 | ✅ **重点** —— 见下方说明 |
| 配饰 | 鲸鱼造型发绳、小胸针 | 不用参考角色的那颗蓝宝石 |
| 比例 | Q 版，约 **2.5 头身** | — |

### 1.3 ⚠️ 为什么「腿必须露出来」

**这是本次设定的核心约束。**

我们要做**逐帧走路动画**。走路动画的本质是「腿在交替」。所以：

- ❌ **不能长裙拖地** —— 裙子盖住腿，走路帧就没有可动的东西
- ❌ **尾巴不能长** —— 会遮挡腿部轮廓
- ✅ **短裙 / 短裤 + 过膝袜** —— 大腿露出，走路帧一眼能看出腿在动

**参考角色的图大多是长裙拖地，这就是我们做不出走路动画的直接原因。原创角色从设计阶段就避开这个问题。**

### 2.3 ⭐ 动作帧清单（**这是"活起来"的关键**）

生成方式参考 `dsh-dfy` 的 `SOURCE.md`：**同一画布生成连续动作图**，再用脚本归一化。

| 动作 | 帧数 | 文件名 | 帧率 | 要点 |
| --- | --- | --- | --- | --- |
| **走路** | **4 帧** | `walk_0` ~ `walk_3` | 8 | ⚠️ **左右腿交替，这是最关键的 4 张** |
| 待机 | 2 帧 | `idle_0` / `idle_1` | 1.5 | 呼吸起伏 |
| 眨眼 | 2 帧 | `blink_0` / `blink_1` | 1 | blink_1 闭眼 |
| 说话 | 2 帧 | `talk_0` / `talk_1` | 6 | 嘴开合 |
| 点击反应 | 4 帧 | `tap_0` ~ `tap_3` | 12 | 不循环 |

**走路帧的画法**：
```
walk_0  左腿前，右腿后，身体微左倾
walk_1  双脚并拢（过渡），身体直立
walk_2  右腿前，左腿后，身体微右倾
walk_3  双脚并拢（过渡），身体直立
```

> 偷懒方案：做不出 4 帧就做 **2 帧**（左右脚各一帧，帧率 6），效果也远好过静态图。

### 2.4 技术要求

| 项 | 要求 | 原因 |
| --- | --- | --- |
| 背景 | **透明 PNG** | 桌宠浮在桌面上 |
| 尺寸 | 单帧 **≥ 512px**（表情 ≥ 1024px） | 缩放不糊即可，512 够用且文件小 |
| **画布** | ⚠️ **所有帧同一画布尺寸、同一坐标** | **否则播放时角色会跳** |
| **脚底** | ⚠️ **始终对齐同一条水平线** | 同上 |
| 视角 | 统一正面或统一 3/4 侧 | 不能混 |
| 光照 | 统一（光从左上来） | 一致性 |

> **`dsh-dfy` 记录的失败教训**：单独生成的帧因为**没保持比例、锚点和步态连续性**被全部弃用。
> **必须做归一化，不能指望 AI 每次画出来都对齐。** 我们也要写一个归一化脚本（检测脚底 → 统一裁切 → 对齐）。

### 2.5 归一化脚本要做的事

生成出来的帧大概率对不齐，需要脚本处理：

```python
# 伪代码，实际实现见素材工作区
for 每一帧:
    1. 裁掉四周透明边（getbbox）
    2. 记录"脚底位置"（bbox 底边）
    3. 按统一画布尺寸重新居中：水平居中 + 脚底对齐到同一水平线
    4. 缩放：让所有帧的角色高度一致
    5. 导出透明 PNG
```

## 四、落地顺序

```
① 用上面的 Prompt 生成 8 张表情 + 走路 4 帧（先生成一版看效果）
      ↓
② 写归一化脚本，把帧对齐（脚底同线、同一画布、同一尺寸）
      ↓

      ↓
④ 若时间充裕，用 See-through 做单图分层，升级成"分层 rig"
   （比逐帧更省素材，效果更接近 Live2D）
      ↓
⑤ 补 ASSETS_LICENSE.md + 生成记录
```

## 五、给团队的话

1. **形象必须原创** —— 这是授权决定的，不是偏好。理由见 `DeepProf_素材授权调研.md`
2. **腿必须露出来** —— 这是能不能做出走路动画的前提
3. **所有帧必须同画布同坐标** —— 这是播放不跳帧的前提
4. **没有动画素材，桌宠就只是"一张会滑动的贴纸"** —— 这是这个模块最核心的交付物
