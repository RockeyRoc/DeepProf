## 三、启动

### 3.1 推荐：双击 `启动桌宠.bat`

```bat
:: 启动桌宠.bat 的内容（摘要）
chcp 65001          :: 让中文日志正常显示
cd /d "%~dp0"       :: 切到脚本所在目录，避免从别处双击时路径不对
npm run dev
```

脚本会先把用法打在窗口里（怎么点、怎么拖、托盘在哪、紧急快捷键），然后启动。

> ⚠️ **关掉这个黑窗口 = 退出桌宠。** 它是 `npm run dev` 的宿主进程，
> 窗口一关，Electron 子进程随之结束。
>
> ⚠️ 注意区分：**关掉桌宠小人的窗口不会退出**（那是「隐藏」，见 3.5）。

### 3.2 开发模式（等价命令）

```bat
npm run dev
```

`electron-vite dev` 会做三件事：

1. 起 Vite dev server 编译 `renderer`，把地址注入环境变量 `ELECTRON_RENDERER_URL`；
2. 编译 `main` 与 `preload` 并启动 Electron；
3. 主进程用 `process.env.ELECTRON_RENDERER_URL` 判断走 dev 还是 prod
   （**这是区分两种模式的唯一依据**，不是 `NODE_ENV`）。

改 `renderer` 下的代码热更新；改 `main` / `preload` 下的代码需要重启（主进程不会自动重载）。

### 3.3 构建与预览

```bat
npm run build     :: 编译产物到 out/（main、preload、renderer 三份）
npm run start     :: electron-vite preview —— 直接跑 out/ 里的产物
```

> ⚠️ `npm run start` **不会重新编译**。如果改了源码没 `build`，预览到的还是旧产物
> （`out/` 里的文件名带内容哈希，源码变了哈希才变，对不上就是没编译）。
> 演示时若发现「新改的功能没出现」，先怀疑这一条。

### 3.5 关窗口 = 隐藏（三条退出路径）

| 操作 | 结果 |
| --- | --- |
| **点桌宠窗口的关闭按钮** | ⚠️ **只是隐藏，不是退出**（`win.on('close')` 里拦下来了）。这样用户误关窗口不会丢桌宠 |
| 托盘图标右键 → **第一项「退出」** | ✅ 真退出 |
| 小人身上右键 → 菜单 → **「退出」** | ✅ 真退出 |
| `Ctrl+Alt+Shift+X` | ✅ 真退出 |
| 关掉 `启动桌宠.bat` 的黑窗口 | ⚠️ **通常能退出，但不保证**（见下） |

> ⚠️ **演示/日常都建议走「托盘第一项」或 `Ctrl+Alt+Shift+X`，不要靠关黑窗口。**
>
> 理由是**没有实测证据**，而代价不对称：
> 代码里**没有任何父进程死亡监听**（没有 `process.on('disconnect')` 之类），
> 所以"关掉黑窗口后 Electron 会不会被一起带走"取决于 Windows 对控制台进程树的处理，
> **无法从代码定论**。
>
> 一旦真的留下了残留实例，下次双击 `.bat` 会因为**单实例锁**直接退出 ——
> 表现是「双击了，什么都没发生」，排查起来很费时间。
>
> **如果确实关了黑窗口**：打开任务管理器搜 `electron`，确认没有残留再走人；
> 或者直接按一次 `Ctrl+Alt+Shift+X` 兜底。

> ⚠️ **托盘菜单第一项就是「退出」**（之后才是分隔线 / 显示隐藏 / 归位 / 自动溜达）。
> 这是刻意的：托盘是唯一在任何状态下都能退出的入口 ——
> 窗口可能被拖到屏幕外，也可能处在点击穿透状态导致右键点不到。

> ⚠️ 所有退出路径都必须先立 `reallyQuitting` 标记，否则会被 close 拦截变成隐藏。
> 代码里 `win.quit` 走的就是 `quitApp()` 而不是裸 `app.quit()`。

## 四、启动后会看到什么（自检清单）

主进程在 `did-finish-load` 后会自动跑一轮自检，**终端日志**是排查问题的第一现场：

| 日志 | 含义 |
| --- | --- |
| `[桌宠] 窗口已显示 @ (x, y) 220x420` | 窗口真的显示了。**没有这行 = 窗口没建出来** |
| `[桌宠] 渲染诊断: {"rootLen":...,"hasPet":...,"petSrc":...,"bodyBg":...}` | `rootLen` 很小或 `hasPet:false` → React 没挂载（白屏） |
| `[桌宠] 窗口自截图已保存: %TEMP%\deepprof-window.png` | 分层/透明窗口用 GDI 抓不到，只能让 Electron 自己抓自己 |
| `[桌宠] 窗口自截图已保存-2s: ...` | 2.5 秒后的第二张。**第一张是空的属正常**（此时 Pixi 贴图还在异步加载） |
| `[桌宠] 快捷键 Control+Alt+Shift+D(归位) ✅ Control+Alt+Shift+X(退出) ✅` | ❌ 表示快捷键被别的程序占用，此时**托盘与右键菜单仍是可靠出口** |
| `[渲染进程] ...` | 渲染进程里 `console.error` / `console.warn` 及以上会被转发到终端 |

> ⚠️ **启动时不再播放「语音链路自检」**。`tts:selftest` 通道仍然存在且可用，
> 但**渲染端没有任何调用方**。要检查神经语音能不能用，在 DevTools 控制台执行
> `await window.deepprof.tts.selftest()`，或在对话面板里念一句听音色。

> ⚠️ **终端会有两类临时诊断日志在刷屏**（作者标注「定位完就删」）：
> `[窗口诊断] resize -> WxH @ (x,y) 来自: ...`（主进程，每次窗口尺寸变化都打）
> 和 `[气泡诊断] 气泡top=... 角色区h=... 窗口h=...`（渲染进程，气泡可见时每 800ms 一次）。
> **它们是排查用的，不是故障。** 演示时若嫌吵，把这两个 `console.warn` / `console.log` 注释掉即可。

### 可选环境变量（不设就完全惰性，不影响正常运行）

| 变量 | 作用 |
| --- | --- |
| `DEEPPROF_PYTHON` | 指定用哪个 Python 跑 `tools/tts/say.py`（默认 `python`；有的机器要设 `py`） |
| `DEEPPROF_SNAP=1` | 开启连拍：每 2 秒抓一张窗口截图到 `%TEMP%\deepprof-window-t1..t10.png`，共 10 张。查动画时用，平时别开（一次启动留 11 个文件） |

```bat

```

| 现象 | 原因 | 处理 |

### 5.2 Electron 起来了，但看不到小人

| 现象 | 排查 |
| --- | --- |
| 窗口建了但屏幕上找不到 | 它可能被挤到屏幕边缘之外。按 `Ctrl+Alt+Shift+D` 归位；或托盘右键「把小人叫回来（归位）」 |

### 5.3 渲染进程白屏 / 报错（按错误信息对号入座）

**`Current environment does not allow unsafe-eval`**
PixiJS 6 内部用 `new Function()` 生成着色器，被 CSP 拦了。
正确解法是 `@pixi/unsafe-eval`（已在依赖里），它把代码在编译期生成好，运行时不 eval。
必须确认 `live2dSetup.js` 里的 `install(PIXI)` 在**任何 Pixi 对象创建之前**执行 ——
`RigPet.jsx` / `FramePet.jsx` 顶部第一行就是 `import './live2dSetup'`，别调换顺序。
**不要为了图省事去放宽 CSP。**

**CSP 相关报错（dev 模式）**
CSP 由主进程按环境注入（`applyCsp()`）：dev 放开 `'unsafe-inline'` 与 `ws:`（Vite HMR 需要），
prod 收紧到只允许自身资源。**CSP 不写在 `index.html` 的 `<meta>` 里** —— 写在那里会把
dev 模式的 HMR 一起拦掉，直接白屏。

**Live2D 切过去黑屏 / 加载失败**
- 确认 `src/renderer/public/live2dcubismcore.min.js` 存在，且 `index.html` 里在
  `main.jsx` **之前**用 `<script>` 引入（它必须挂出 `window.Live2DCubismCore`）；
- 本项目只用 Cubism 4（`.moc3`），import 路径是 `pixi-live2d-display/cubism4`；
- `live2dSetup.js` 里挂 `window.PIXI` 这一步不能省，否则 Cubism 4 支持会被静默禁用。

**主进程报 `Cannot find module './xxx'`**
不要拆分 `src/main/` 下的文件。`electron.vite.config.mjs` 用了 `externalizeDepsPlugin()`，
它会把相对路径的 `require` 保留为外部依赖，拆分后的文件在运行时找不到 ——
这正是 Mock Runtime 与性能探针都写在 `main/index.js` 里的原因。

**点了「点击穿透」之后点不动任何东西，也关不掉**
✅ **已修复（核对于 2026-09-19）**：`App.jsx` 的 `toggleThrough()` 现在按 `next` 传参，
再点一次右键菜单的「恢复鼠标操作」即可关掉。
历史情况（下面这段不要再照着修）：`App.jsx` 的 `toggleThrough()` 无论开还是关都传 `true`，
而它只能从右键菜单进入（进去就关掉菜单）—— **那时强制穿透开了之后在界面上关不掉**，
规避办法是重启桌宠，或先在面板里打开对话（`uiOpen` 为真时主进程会临时不穿透）。
契约侧 `../shared/contracts/INCONSISTENCIES.md` 第 30 条还停在旧状态上，**以代码为准**。

### 5.4 语音有问题

| 现象 | 说明与处理 |
| --- | --- |
| 音色像客服播报、很平 | 走的是 **Chromium 系统语音**（降级了）。检查 `pip install edge-tts` 装了没、网络通不通、`DEEPPROF_PYTHON` 对不对 |
| 界面显示「本机不支持语音合成」 | `window.speechSynthesis` 或 `SpeechSynthesisUtterance` 不可用（系统语音也没有）。检查系统是否装了中文语音包：Windows「设置 → 时间和语言 → 语音」 |
| 念到一半停了 | Chromium 已知问题：长文本会被静默截断（约 15 秒）。`tts.js` 已按句子切块（每块 ≤60 字）绕开 |
| 点「暂停」后「继续」不动 | Chromium 的 `pause()` 后立刻 `resume()` 有时会卡住。这是已知问题，UI 上以「停止朗读」为主操作 —— 停止走 `cancel()`，不受影响 |
| 点了「停止朗读」还在响 | 不应该发生 —— `stop()` 会同时停掉两个引擎（`<audio>` 与 `speechSynthesis`）。若复现请记录：当时用的是哪个引擎（DevTools 里 `window.deepprof` 所在的 `tts.js` 导出 `engineName()`） |
| 听不到启动自检的声音 | ✅ 正常。启动自检里**已经没有** TTS 那一项了（见第四节） |

## 六、给演示/评审的最短路径

```bat
:: 1. 启动
双击 启动桌宠.bat

:: 2. 让它动起来（右键小人）
让它自己走         → 看分帧走路 + 转身翻面（注意：漫游默认是关的，先点这一项）
随便走走           → 立刻走一次
打开对话           → 窗口展开成面板
正常回复           → 6 个教学节点依次走过：讲解 / 提问 / 提示 / 纠错 / 更新学情，
                     流式文本 + 语音朗读（约 9~10 秒）
取消               → 文本停住 +「（已中断）」+ 语音立刻停
报错               → 错误气泡 + 事件日志里的 model.failed / agent.failed
重连               → 「连接中断，重连中…」→ 回待机（历史消息不重复）
教学动作（面板底部）→ 逐个点 Assess/Teach/Ask/Hint/Correct/Test/UpdateProfile/Reflect，
                     看「教学动作 → 表情」的映射（其中 Test 与 Reflect 只能从这里看到）
右键「换成分层走路」→ 切到分层 rig 模式（走路有腿，但注意 Correct 无专属表现）

:: 3. 收尾
Ctrl+Alt+Shift+X   → 退出（托盘第一项也可以）
```

失败场景的**预期现象**与**为什么算通过**逐条写在
[`失败样例.md`](失败样例.md) 里，演示时可以照着对。
事件契约与 IPC 的权威定义在 [`../../shared/contracts/`](../../shared/contracts/)。
