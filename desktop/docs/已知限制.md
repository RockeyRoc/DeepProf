## 一、学习者用不到的能力（功能缺口）

### 1.1 🔴 ASR 未接入 —— 任务书明写要接，只做了 TTS

- **是什么**：任务书 §16.4 任务③原文是「接入 **ASR/TTS** 与可中断播放」。
  本轮**只完成了 TTS**（神经语音为主 + 系统语音兜底 + 可中断），**没有语音识别**。
- **影响什么**：**学生说话，桌宠听不见。** 交互入口只有「点小人」和「打字」两种，
  与"语音学伴"的产品设想差着一整条输入通道。
- **为什么没解决**：Electron 内置的语音识别依赖 Google 的在线服务，
  **在当前网络环境下不可用**。要做必须走后端（自建或接第三方 ASR），
  而后端本轮不存在（见 1.3）。这不是"没时间做"，是**没有可用的落点**。
- **现在的处置**：未处置，也未排期。界面上的「自动朗读」开关只管输出，不管输入。

### 1.2 🔴 Live2D：一条三方互相锁死的死结

- **是什么**：任务书 §16.4 第二条要求「先用 PNG 跑通表情状态，**再接 Live2D**」。
  现状是 **PNG 这一半通了，Live2D 这一半卡死**。三个事实互相锁住：

  | # | 事实 | 证据 |
  | --- | --- | --- |
  | 1 | 现有 Live2D 链路**只能**跑官方 Haru 样例模型 | `Live2DPet.jsx` 走 `pixi-live2d-display/cubism4` |
  | 2 | Haru 是 Live2D 官方素材，**授权上不能进交付物** | 已于 2026-09-19 移出；`src/renderer/public/` 现已**空目录**，`index.html` 里那行 Cubism Core `<script>` 也已删 |
  | 3 | 换成**原创角色**的 Live2D 模型 → **零进度、无人排期** | `交付说明.md` §四 |

- **影响什么**：
  - 右键菜单里的 Live2D 入口**本轮不提供**，点了只弹一段说明文字（`App.jsx` 的菜单项「Live2D 本轮不提供（当前使用逐帧 PNG 方案）」）。
  - `Live2DPet.jsx` 成了**永远走不到的死代码**（靠 `React.lazy` 挂着，永不被求值）。
  - **「有切换入口」≠「任务完成」** —— 按任务书字面，这一条**没有交付**。
- **为什么没解决**：**这不是技术问题，是决策问题。** 技术路径清楚（做原创模型），
  但原创 Live2D 建模的工作量没人认领、也没排期。
- **现在的处置**：⚠️ **本次交付唯一一条「不做决定就过不去」的缺口。**
  两条路二选一，需要负责人拍板：
  ① 排期做原创角色的 Live2D 模型；
  ② 正式报备：**改由逐帧 PNG 方案承接**第二条任务，Live2D 移出本轮范围。
  代码里已经按"这是有意的取舍"写好了注释（避免下一个人以为是坏了），但**决策本身还没做**。

### 1.3 🟠 真实后端未接 —— 全部事件来自 Mock

- **是什么**：所有事件都由主进程里的 `MockRuntime` 产生（`src/main/index.js` 的 `SCRIPT` 常量）。
  本轮复核：**`src/` 全目录 0 处** `fetch` / `WebSocket` / `http.request` —— 没有任何网络代码。
- **影响什么**：
  - 界面上的"回复"**不是真回答**，是 6 段写死的教学用语（末尾刻意挂了一句「以上是 Mock 演示数据」）。
  - 没有超时、没有重试退避、没有断线重连的真实语义。
  - §18.2 的 `SessionRequest` 四字段凑不齐：前端只发 `session_id` + `content`，
    **没有 `learner_id`、没有 `request_id`**（全目录 grep 无匹配）。
- **为什么没解决**：后端模块不由本模块负责，本轮不具备联调条件。
- **现在的处置**：Mock 放在**主进程**而不是渲染层（`README.md` §五 决策 1），
  将来换真后端**渲染层一行都不用改**。这是本轮唯一的对冲。

### 1.4 🟠 偏好上报是断头路 —— 前端全写好了，没有后端端点

- **是什么**：`petStats.js` 的 `exportForDataTeam()`、授权开关（`consent`，默认**关闭**）、
  授权面板 UI、主进程 `pref:export`、preload 的 `exportPreference` **全部就位**。
  但 `pref:export` 干的事是**把 JSON 写到本机桌面的 `DeepProf_偏好更新/` 文件夹**。
- **影响什么**：**数据组收不到任何东西。** 好感度 / 心情 / 精力只留在本机 `localStorage`。
  任务书 §16.4 交接要求里的「向数据组提交经用户授权的偏好更新」**只完成了"经用户授权"这一半**。
- **为什么没解决**：没有后端端点可发；本轮也不具备联调条件。
- **现在的处置**：未处置。导出文件格式就是将来要对接的数据契约，
  见 [`../交接清单.md`](../交接清单.md) §3.2 / §3.3。

### 1.5 🟠 `pet/` 目录从未建立 —— 交付物结构和任务书对不上

- **是什么**：任务书 §16.4 写的模块范围是 **`desktop/` · `pet/` · `../../shared/contracts/`**。
  现状：`../../shared/contracts/` 存在，`desktop/` 存在，**`pet/` 从未建立** ——
  桌宠代码**全部**在 `desktop/` 下。
- **影响什么**：**评审若照任务书去找 `pet/`，会找不到。**
  这是交付物结构与任务书之间的显式不一致，不是疏漏可以带过的。
- **为什么没解决**：拆目录等于把所有相对路径、构建配置、启动脚本重排一遍，
  在交付前夜做这件事**风险远大于收益**（`desktop/` 下一直有并发改动）。
- **现在的处置**：未改动。**建议按"交付物结构变更"向负责人报备一次**，
  而不是留到评审现场被问。

### 3.2 🟠 多显示器 / 高 DPI 未适配

- **是什么**：窗口定位与夹取**只取 `screen.getPrimaryDisplay()`**，
  完全没有 `display-metrics-changed` / `display-added` / `display-removed` 监听。
- **影响什么**：
  - 演示现场接了投影/副屏时，**小人可能出现在评审看不到的那块屏上**（或反之）；
  - 演示中途插拔显示器或改缩放，窗口可能停在已不存在的工作区坐标上；
  - 小人被拖到副屏后按「回到原位」，会被**强行拉回主屏**。
- **为什么没解决**：本轮没有多屏环境可验证；改动涉及五处调用点，时间不够。
- **现在的处置**：**不需要改代码的兜底** —— 演示前把投影设成「复制」而不是「扩展」，
  并按一次 `Ctrl+Alt+Shift+D`（归位）确认小人在主屏可见。详见 `可移植性清单.md` R6。
- 📌 **关于"高 DPI 会不会让角色大小出错"**：本轮复核结论是**不会** ——
  Pixi 的布局链不经过 `devicePixelRatio`，角色尺寸与系统缩放**无关**。
  详细的验算过程见 `可移植性清单.md` §1.1 与 §5。**这条已经从"未知风险"降级为"已查清"。**

## 四、🔴 隐私（**最需要评审注意的一节**）

### 4.1 自动朗读**默认开启**，会把用户的提问送到微软的 TTS 服务器

- **是什么**：这是一条**真实的对外数据发送**，链路如下（每一环本轮都核对过）：

  | 环节 | 位置 | 事实 |
  | --- | --- | --- |
  | ① 默认值 | `src/renderer/src/App.jsx` | `const [autoSpeak, setAutoSpeak] = useState(true)` —— **默认开** |
  | ② 触发 | 同上，`model.completed` 分支 | 收到回复完成事件就**自动**调 `speak(reply)` |
  | ③ 通道 | `tts.js` → preload `tts.synthesize` → 主进程 `tts:synthesize` | 主进程**起一个 `python` 子进程**跑 `tools/tts/say.py` |
  | ④ **出网** | `tools/tts/say.py` | `edge_tts.Communicate(text, ...).save(out)` —— `edge-tts` 走**微软的在线合成端点** |

- **关键的一点（容易被忽略）**：送出去的**不只是回复本身**。
  `model.completed.text` 的第 1 段是 `SCRIPT.Assess(input)`，它**原样带上了用户输入的前 24 个字**
  （实测 payload：`"你问的是「帮我讲讲数据库第三范式」。…"`）。
  也就是说 —— **用户什么都没设置，第一次提问的内容就会被送到微软服务器。**
- **影响什么**：
  - **对学生的承诺与实际不符**：授权面板上写着「下面的数据默认不出本机，开关不开就一个字节也不发」，
    但那句话说的是**偏好统计数据**；**语音这条链路是另一回事，默认就在出网**，界面上没有任何提示。
  - 与项目自己的纪律冲突：`可移植性清单.md` §5 明确记了「接真实云端 TTS 时，密钥必须留在主进程」——
    密钥确实留住了，但**内容**没有。
- **送出范围的边界（不要夸大）**：送出的**只有文本**，且被截断到 **600 字符**
  （主进程 `t.splice(0,600)`）；不含 `learner_id`、不含凭据、不含本机其他数据。
- **为什么没解决**：神经语音要联网是 `edge-tts` 这个选型本身的性质，
  换本地 TTS 音质会掉一个数量级（那是当初选它的原因）。
  **问题不在于"它联网"，而在于"默认开、且没告诉用户"。**
- **现在的处置**：
  - 界面上有「🔊 / 🔇 自动朗读」开关，**关掉之后不再合成、不再出网**；
    演示时若网络或隐私敏感，**提前点成 🔇**（换成手动「朗读最新回复」）。
  - ⚠️ **但这不够** —— 默认值是开的。**建议在交付前至少做一条**：
    ① 把默认值改成 `false`；或 ② 首次自动朗读前弹一次明确告知（"朗读需要联网，会把回复文本发送到微软的语音服务"）。
    **本轮没有改，因为改默认值属于行为变更，需要负责人确认。**
- **未验证**：具体的请求域名与请求体是 `edge-tts` 包的内部实现，**本轮没有抓包验证**，

### 4.2 🟢 偏好数据：本地留存 + 导出到桌面，没有任何网络发送

### 5.1 🟠 `pedagogy.decision` 缺 v0.4.1 的 11 个必填字段

- **是什么**：本轮实测抓到的 payload **只有两个字段**：

- **影响什么**：v0.4.1 为「实验复盘」新增的必填内容一个都没有 ——
  含 `capability` / `capability_status` / 依据字段（`evidence_sufficient` 等）/ `answer_leaked`，**共 11 个**。
  没有它们，**实验复盘无从做起**（这正是 v0.4.1 加它们的理由）。
- **为什么没解决**：后端还没实现；前端只能照抄已有的两个字段。
- **现在的处置**：字段清单已登记在 `../../shared/contracts/events.json` 与
  [`../../shared/contracts/INCONSISTENCIES.md`](../../shared/contracts/INCONSISTENCIES.md)，等后端补。

### 5.2 🟠 §7.3 装配/绑定失败：桌宠**分不清**「装配失败的空回复」和「没话说」

- **是什么**：`CapabilityResult.status`（六态）是 `RuntimePort.execute` 的返回值，
  **在「图 ↔ Runtime」之间传递，不走事件流**。事件流里没有任何字段承载它。
- **影响什么**：v0.4.1 §7.3 要求装配失败「**响亮地暴露**」，

- **现在的处置**：未实现。建议写进 `pedagogy.decision.capability_status`（与 5.1 是同一件事）。

### 5.3 🟠 静默失败：任何没同步映射表的新教学节点，都会**无声无息退回待机**

- **是什么**：`resolveAnimation()` 末尾的 `|| 'idle'` 兜底仍在。
- **影响什么**：后端新增一个节点名、前端忘了同步映射表时，
  **不报错、不崩溃、不掉帧，只是没有任何专属表现** ——
  而"待机"恰好也是没有教学节点时的**正常**表现，所以**从现象上完全看不出这是 bug**。
  验收时后端发得对、前端也没崩，**只有逐帧盯着小人看才会发现**。
- **为什么没解决**：这是刻意的兜底设计（避免崩溃），代价是静默。
- **现在的处置**：⚠️ **对后端的硬要求**：新增节点名前必须通知前端同步补映射，
  **不能指望测试暴露问题**。且要**同时补两处**：`petAnimations.js` 的映射表

## 七、本轮复核新查到的四条（之前没人记过）

> 这四条都是 **2026-09-19 18:1x–18:2x** 实际启动应用、对着终端与 DOM 观察到的，
> 不在 `README.md` §六 与 `交付说明.md` §四 的清单里。

### 7.1 🟠 启动自检的 `hasPet` 探针**永远是 `false`** —— 它在查一个不存在的选择器

- **现象**：启动日志里 `[桌宠] 渲染诊断: {"rootLen":186,"hasPet":false,...}` ——
  但**画面明明是正常的**（角色渲染出来了）。
- **根因**：主进程的自检探针查的是 `document.querySelector('.pet')`，
  而 `App.jsx` 渲染出来的类名是 **`.pet-area`**（相关类名还有 `.pet-host` / `.pet-wrap` / `.pet-bubble`，
  **没有任何元素类名正好是 `pet`**，全目录 grep 无匹配）。
- **影响什么**：这条诊断本来就是为"白屏时判断 React 有没有挂上"准备的，
  现在它**永远报 `false`** —— 真的白屏时，它给不出任何区分度，等于白做。
  ⚠️ **更危险的是**：这份日志会被写进交付文档当作"自检通过"的证据，
  而它实际上**恒为 false**。
- **处置**：建议把选择器改成 `.pet-area`。**本轮未改**（属代码改动）。

### 7.2 🟠 geometry 自检**在贴图加载前误报**，把终端刷满

- **现象**：终端被同一条告警刷屏（实测一次启动刷了 **20+ 条**，且持续不断）：
  ```
  [渲染进程] [桌宠] ⚠️ 素材与 geometry 对不上：贴图是 %dx%d，geometry 写的是 %dx%d。
             角色大小会错。请重跑 归一化帧.py，并把 PNG 和 _几何.json 一起重新拷贝。 1 1 1536 1536
  ```
- **两个独立的问题叠在一起**：
  1. **误报**：`FramePet.jsx` 里 `if (tex.width && geo.canvas_w && tex.width !== geo.canvas_w)` ——
     Pixi 的贴图在**加载完成前** `tex.width` 是占位值 **1**，于是 `1 !== 1536` 成立，**每次渲染都报一次**。
     素材其实是**对得上**的（都是 1536）。
  2. **参数没有替换**：这句用的是 `console.error` 的 `%d` 占位符，
     但渲染进程的 `console.error` 是**经 IPC 转发到主进程**再打印的，
     转发时参数被转成字符串拼接，**`%d` 原样留着**，值被甩在句尾（就是结尾那串 `1 1 1536 1536`）。
- **影响什么**：这条自检是**为了防 768/1536 那个坑**专门加的（加得对），
  但现在它**每次启动都在喊狼来了**。真正出问题时，这条告警会被淹没在刷屏里 ——
  **一个防静默失败的检查，自己变成了噪音。**
- **处置**：建议 ① 等贴图 `onload` 之后再校验（或加 `tex.valid` 判断）；
  ② 改成结构化输出（`console.error('...', {tex:..., geo:...})`）避免 `%d` 转发丢失。
  **本轮未改**（属代码改动）。

### 7.3 🟢 事件日志面板：只有 `type` + `source`，且只留最近 200 条

- **现象**：展开「事件日志 N」后，每行只有两个字段 —— 事件类型与来源（`runtime` / `renderer`）。
  **看不到 payload**。一轮「正常回复」实测产生 **107 条**事件，面板显示 `事件日志 107`。
- **影响什么**：**payload 是排查时最需要的东西**（`node` 名、`reason`、`code` 全在里面），
  现在只能靠终端或 DevTools。且**连点几轮就会顶掉前面的**（上限 200），
  想回看第一轮的事件序列会已经被挤掉。
- **处置**：未处置。演示时若需要展示 payload，用 DevTools 的
  `window.deepprof.onEvent(e => console.log(e))` 现场挂一个（**本轮就是这么抓的序列**）。

### 7.4 🟠 每一轮都会把 `pedagogy.node.entered{Assess}` **发两遍**

- **现象**：实测抓到的序列里，`Assess` 节点在一次「正常回复」中被 **entered 了两次**：
  ```
  pedagogy.node.entered {node:"Assess"}     ← 来自 run()
  model.requested {provider,model}
  pedagogy.node.entered {node:"Assess"}     ← 来自 runScript()，si=0 又发了一次
  pedagogy.decision {next:"Teach", ...}
  ```
- **根因**（代码与实测双证）：`run()` 自己发了一次 `pedagogy.node.entered{Assess}`，
  500ms 后调 `runScript()`，而 `runScript()` 走第一个节点时**又发了一次**。
- **影响什么**：
  - 前端**看不出来**（`setNode` 幂等，画面正常）—— 又是一处**静默的重复**。
  - 但 `event_id` + `sequence` 去重**拦不住它**：这是**两条新事件**，不是重发。
  - 接真后端后，如果后端也按"一次进入一条"计数，**复盘数据里 Assess 会多算一次**。
- **处置**：未处置（属代码改动）。建议删掉 `run()` 里那一行，或删掉 `runScript()` 的 si=0 分支。

## 九、2026-09-19 晚修掉的五个缺陷（**都是"静默失败"，值得留档**）

这一节记的是当晚联调时暴露、并已修复的问题。**留档的原因不是"修好了"，
而是它们的失败模式完全一样：不报错、不崩溃、没有任何提示，只是"表现不对"。**
这类问题在联调时最难发现，因此把识别方法一并写下来。

### 9.1 `runtime` 从未被实例化 —— 演示按钮全部失效 🔴

`src/main/index.js` 里 `let runtime = null` 之后**全工程没有任何一处给它赋值**
（`class MockRuntime` 定义在那里，是死代码）。而 `session:send` / `cancel` / `reconnect`
三个 IPC handler 直接解引用它。

- **现象**：点「正常回复」「加载中」「报错」「重连」**什么都不发生**；
  事件日志始终 0；「取消」按钮从不出现。渲染端拿到的是
  `TypeError: Cannot read properties of null`。
- **影响面**：四条验收里的第 2、3 条**被完全阻断、无法验证**；
  桌壳之外只剩纯本地功能（摸头、漫游、置顶、穿透、好感度）。
- **同时坏了两条路**：编译产物 `out/main/index.js` 里也是同样的空洞，
  所以 `npm run dev` 和 `npm run start` **都坏**。
- **已修**：补回 `initRuntime()`（实例化 + `runtime.on('event')` 转发到渲染进程），
  并给三个 handler 加了 `runtime_not_ready` 防呆 —— 将来再断线会**响亮报错**，
  不会再表现为"点了没反应"。
- **修复验证**：一轮完整对话收到 **237 个事件 / 11 种类型**（含
  `agent.turn.completed`、`model.completed`），`sequence` 201/201 非 null 且单调递增，
  `event_id` 全部唯一。修复前是 **0**。

> **识别方法**：文档 `输入输出.md §〇` 画了完整链路
> （`MockRuntime → win.webContents.send('runtime:event')`）。
> 核查时**不要只看类定义在不在，要搜"谁给它赋值"** —— 声明与使用都在、唯独装配缺失，
> 是这类问题最典型的形态。

### 9.2 `ANIMATIONS.talk` 填了帧，但没有任何路径会切到它

`petAnimations.js` 里 `talk` 的 `frames` 早就填好了 2 帧，
但 `STATUS_TO_ANIMATION` 里**没有 `streaming` 这一条**，而全工程也没有别处引用 `talk`。

- **现象**："说话嘴部开合"始终达不成 —— 流式期间播的一直是教学节点那张**静态**表情
  （`teach.png`），嘴部只有呼吸滤镜在模拟。
- **已修**：`STATUS_TO_ANIMATION` 补 `streaming: 'talk'`。

> **识别方法**：改了 `ANIMATIONS` **不等于**改了表现。
> 验证一个动画是否真能播，要**从 `resolveAnimation` 往回查**：
> 有没有哪条路径会返回这个键。只 grep `ANIMATIONS.xxx` 的定义处看不出问题。

### 9.3 加 overlay 时漏判 `null` —— 渲染期抛异常，React 卸载整棵树 🔴

为眨眼给 `FramePet` 加 overlay 时写错了一个判断：

```js
const oKey = oFrames.join('|') + '#' + (overlay ? overlay.trigger || 0 : 0)
if (oKey && overlayRef.current.key !== oKey) {
  holds: overlay.holds || null     // ← overlay 为 null 时抛 TypeError
```

`overlay` 为 `null` 时 `oKey` 会拼成 `"#0"` —— **这是个真值**，于是进了分支去读 `null.holds`。
而 `App.jsx` **只在待机时传 overlay**（其它动作传 `null`），
所以**只要一切换动作就抛异常**。

- **现象**：抛在**渲染期** → React 卸载整棵树 → **桌宠窗口变成纯空白，角色完全消失**。
- **已修**：先判 `overlay` 再算 `oKey`。
- **教训（写下来给下一个人）**：给渲染组件加**可选参数**时，
  **必须连 `null` 分支一起测** —— 只测"正常路径"等于没测。
  这个 bug 是在上一个 bug（9.4）修完、去测待机以外动作时才暴露的。

### 9.4 两条路径同时写 `sprite.texture` —— 高频闪烁

同一件事：`showFrame`（基础动画）和 `showActiveFrame`（overlay）**都在写 `sprite.texture`，
而且同一帧里都会跑**，两张图每帧互相覆盖。

- **现象**：角色**高频闪烁**（用户原话"在闪"）。
- **已修**：重写成**单一路径** —— `wantedUrl()` 决定显示哪张，`applyTexture()`
  统一应用，基础动画与 overlay **只推进各自的索引、都不碰贴图**。
  规则：**任何时候只允许一条写贴图的路径。**

### 9.5 眨眼帧 / 说话帧：身体被画宽了 5%~12%

即梦出图时没有走「**局部重绘**」，而是整张重生成，导致角色**整体被画宽**：

| 帧 | 整体宽（相对 idle） |
| --- | --- |
| `blink_1`（闭眼） | **×1.119** |
| `talk_1`（张嘴） | **×1.053** |

- **现象**：嘴一开一合、眼一闭一睁，角色**鼓一下瘪一下**（用户原话"感觉她在变胖"）。
- **为什么归一化没救**：归一化只统一**高度**，不统一宽度。
- **已修（临时方案）**：`对帧.py` 新增 `--横缩` / `--横缩_`（**只压横向、不改高度**，
  因为等比缩放会把角色改高，是拿一个问题换另一个）。
  压完四帧整体宽 623/624/624/625，段宽比全部在 1.00~1.02。
- **⚠️ 根因没解决**：这是**压回来**的，不是重画的。脸横向窄了 5%/12%，
  1200px 高的角色上大约窄 15px，肉眼基本看不出，但**属于取巧**。
  **正确做法是重新出图时走「局部重绘」**（`DeepProf_生图Prompt包.md` §3.2 末尾
  已经写明了这个做法）。当前受限于即梦积分，本轮先用压缩顶。
- **附带发现**：`blink_1` 的表情是「眯眼笑 + 红晕」，不是中性的闭眼。
  眨眼时脸会从平静跳到开心，观感偏"卖萌"。**尚未处理，属素材问题。**

> **识别方法**：新增动作帧后，**除了看高度对齐，还要量宽度**。
> 高度一致但宽度不一致，表现就是"角色在呼吸式地变胖"。
> 量宽度的现成命令见 `../tools/素材流水线/对帧.py` 的运行输出。

### 9.6 一条**假警报**：`各帧头部水平位置相差 82~125px`

归一化脚本在压缩后会报这条警告，但**实测四帧的头区中心分别是
768.0 / 766.5 / 767.5 / 767.0**（画布中心 768）—— **偏 1.5px，不会左右晃**。

原因：告警用的是 `measure_char` 的 `head_cx`，它在横向压缩后检测失准。
**这条警告目前是误报，不要照着它去调对齐。**
