## 1️⃣ 取消：三个问题 【要刘俊鹏回】

对账时发现**前端契约和后端实现在「取消」上对不上**。详细版见
`shared/contracts/_待确认_取消事件分歧.md`，这里只放结论。

**(a) 取消到底发哪个事件？**

| | 发什么 |
| --- | --- |
| Mock（前端自演） | `agent.failed({reason:'cancelled'})` |
| **真后端** | **`agent.cancelled({reason:'cancelled'})`** |

后端里 `AGENT_CANCELLED` 和 `AGENT_FAILED` 是**两个并列的独立类型**。
契约当初照 Mock 写，所以写了句「agent.failed 是取消的唯一表达方式」——**对真后端不成立**。

> **建议**：统一到 `agent.cancelled`，**改 Mock 而不是改后端**（后端有测试锁死了这个名字）。

**(b) `agent.cancelled` 不在「终结事件」名单里**

```python
_TERMINAL_TYPES = {AGENT_TURN_COMPLETED, AGENT_FAILED}   # ← 少了 AGENT_CANCELLED
```

目前靠订阅关闭兜住了、没暴雷，但名单漏了个终态。

**(c) 后端没有显式取消接口（这条最影响验收）**

`api/` 里翻遍了，**没有** `POST /sessions/{id}/cancel`。现在唯一能取消的办法是**客户端断开 SSE**。死结：

```
前端想取消 → 只能断开 SSE
          → 服务端才触发 CancelledError → 发 agent.cancelled
          → 但这条 SSE 已经断了，事件发不出去
          → 前端永远收不到「取消成功」的确认
```

而「流式文本与语音**可停止**」是 §16.4 的验收项，设计文档 §952 也把「退出可取消」列为里程碑门槛。

> **前端已经容错**（两个事件都接），所以**不影响现在演示** —— 是**接真后端时会踩**。

**要你回**：①②③ 三个 yes/no。

## 2️⃣ 新角色的美术源，有分层吗？ 【要组长回】

**Live2D 是设计文档里已确认的方向，不是"要不要做"**：

- `D-1`（已确认）：「桌面端使用 Electron + React，**Live2D**/PNG 和语音通过受控接口接入」
- §16.4 第二条：「先用 PNG 跑通表情状态，**再接 Live2D**」
- 门户的桌面端学习资料：「Live2D Cubism 示例 —— 先跑官方样例，**再接自有模型**」

**卡点是素材形态**：Live2D 不是丢一张图进去就会动，它要**把角色拆成 20~30 个可独立变形的图层**
（后发 / 前发 / 脸 / 左右眼白 / 左右瞳孔 / 左右上眼睑 / 眉毛 / 嘴（3 个口型）/ 脖子 / 双臂 /
双腿 / 配饰……）。现在手上是 **6 张合成好的平面 PNG**，导进去只是一张纸片。

**代码链路早就通了**（`Live2DPet.jsx` 在仓库里、官方样例模型跑通过），不是技术问题。

### ⚠️ 这条反直觉，请重点看

**转 Live2D 之后，那 6 张图就不用出了** —— 眨眼、说话、头发飘全是骨骼驱动。

| | 继续 PNG | 转 Live2D |
| --- | --- | --- |
| 美术还要出 | 眨眼 1 + 说话 1 + 走路四格 1 + 补 hint/correct/quiz 3 = **≈6 张图** | **分层源 1 份（~30 层）** |
| 谁做 | AI 出图即可 | 美术手工分层 + Cubism Editor 逐层绑定 |
| 效果 | 逐帧，够用 | 头发飘、呼吸、视线跟随 |
| 我这边工时 | 很快（流水线已写好） | 要重写渲染接法 + 调参 |

**所以要回的就一句：新角色的美术源，是有分层的，还是只有合成好的平面图？**

> 详细清单（每层叫什么、格式要求）见 `desktop/docs/_待确认_Live2D分层源.md`。

## 4️⃣ 情感词表三套合一 【要孙一新回】

| 来源 | 取值 |
| --- | --- |
| `graph/education/policies/__init__.py` 的 `EMOTION_BY_ACTION` | explaining · **curious** · encouraging · **patient** · **attentive** · **supportive** · warm |

> **前端的 emotion 优先级高于教学节点。**所以如果后端改走 `pet/emotion.py` 的词表，

| 教学动作 | pet/emotion.py 给的情绪 | 前端显示 | 按教学节点应该是 |
| --- | --- | --- | --- |
| **Ask** | `thinking` | **思考** | **提问** |
| UpdateProfile | `neutral` | 待机 | 高兴 |
| Assess | `neutral` | 待机 | 思考 |

（现在用 `graph` 词表是**全对**的，0 处冲突 —— 所以这是"后端若改词表"的隐患。）

**要你回**：三套统一到哪一套？以及 `Ask` 到底该表现为"一起想"还是"邀你来答"？
