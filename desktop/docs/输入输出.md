## 一、输入 A：事件流（主要输入）

### 1.1 公共外壳（envelope）

每条事件都是这 **8 个字段**，由 `makeEvent()` 组装：

| 字段 | 类型 | 示例 | 说明 |
| --- | --- | --- | --- |
| `event_id` | string | `evt_m1a2b3c4d_7` | 唯一标识，`evt_<base36时间戳>_<自增序号>` |
| `session_id` | string | `sess_m1a2b3c4d_1` | 会话标识。Mock 里是**进程级常量**，多轮对话共用 |
| `trace_id` | string \| null | `trace_m1a2b3c4d_9` | 一轮「发问 → 回答结束」的追踪标识。⚠️ **`reconnect()` 路径下为 `null`** |
| `sequence` | integer | `42` | ✅ **新增**。事件序号，前端靠它去重。⚠️ Mock 用的是**进程级全局计数器**（不是按 session 分组），当前只有一个 session_id 所以等价 |
| `timestamp` | string | `2026-09-19T04:31:07.812Z` | ISO 8601 UTC，毫秒精度 |
| `type` | string | `model.stream.delta` | 事件类型 |
| `payload` | object | `{ delta, index }` | 载荷，字段见下表 |
| `source` | string | `runtime` / `renderer` | 来源。Mock 只用这两个值（取消场景为 `renderer`） |

> **关于 `sequence` 与验收项「断线重连不重复展示」**
> §18.2 要求这个字段，前端已按 `event_id` + `sequence` **双重去重**（见 `handleEvent` 开头的
> `seenIdsRef` / `lastSeqRef`）。所以这条验收项现在**技术上成立了**，
> 不再依赖「Mock 重连时不补发历史事件」这个巧合。
>
> ⚠️ 但要注意：Mock 每次重连都产生**新的 `event_id` 与新的 `sequence`**，
> 所以**连点 N 次「重连」仍会看到 N 条一样的提示** —— 去重针对的是「后端重发同一条事件」，
> 不是「用户重复触发」。这是两回事。

### 1.2 十五种已实现事件

`发出时机` 指 Mock 的实际行为。⚠️ **正常一轮现在会走完 6 个教学节点**，
所以下表的「一轮发几次」与 v0.4 时代（只走 Assess + Teach）完全不同。

| # | type | payload 字段 | 一轮发几次 | 渲染进程的反应 |
| --- | --- | --- | --- | --- |
| 1 | `session.started` | `resumed: boolean`（**恒为 false**） | 1 | 与 #2 同一分支：进 `loading`、清空流式缓冲、`node` 置空、打开气泡、**打断语音** |
| 2 | `agent.turn.started` | `input: string`（用户原文，**未脱敏**） | 1 | 同上 |
| 3 | `pedagogy.node.entered` | `node: string`（PascalCase） | **6**（Assess / Teach / Ask / Hint / Correct / UpdateProfile） | `setNode(node)` → 驱动教学节点标签与动画 |
| 4 | `pedagogy.decision` | `next: string`（下一个节点）<br>`reason: string`（中文，给人看）<br>⚠️ **缺 v0.4.1 要求的 11 个字段**（`capability` / `capability_status` / `node` / 依据字段 / `answer_leaked`） | 1 | ⚠️ **无处理**，只进事件日志 |
| 5 | `memory.read` | `query: string`（Mock 为 `recent_mistakes`；§7.1 定义的是结构化 dict） | 1 | ⚠️ **无处理** |
| 6 | `model.requested` | `provider: string`（`deepseek`）<br>`model: string`（`deepseek-chat`） | **1**（整轮只发一次） | 维持 `loading` |
| 7 | `model.stream.delta` | `delta: string`（**累计全文，不是增量**）<br>`index: integer`（**已产出字符数，不是分片序号**） | **6 段 × 约 N 片**（每 22ms 一片、每片 +4 字符） | 进 `streaming`，**覆盖**气泡文本，显示光标；`talking=true` 驱动说话动作 |
| 8 | `pedagogy.node.exited` | `node: string` | **6**（与 entered 一一配对） | ⚠️ 无处理 |
| 9 | `memory.write` | `dimension: string`（`episodic`）<br>`key: string`（`db_normalization`）<br>⚠️ 缺 §5.5 要求的 `source`/`confidence`/`ttl`/`revocable` | 1 | ⚠️ 无处理 |
| 10 | `model.completed` | `text: string`（6 段拼接后的完整回复） | **1**（整轮只发一次） | 入库一条 pet 消息并触发自动朗读。取的是**累积流式缓冲**；缓冲为空时**退回 `payload.text`**。随后回 `idle`、安排气泡 5 秒后收起、好感度 `chat` 计一次 |
| 11 | `agent.turn.completed` | `status: string`（`ok`） | 1 | 回 `idle`，气泡 5 秒后收起 |
| 12 | `model.failed` | `code: string`（`RATE_LIMIT` / `CONN_RESET`）<br>`message: string`（中文） | 0 或 1 | 进 `error`，插入一条系统消息 **`模型失败：{message \|\| code}`** |
| 13 | `agent.failed` | `reason: string`（`cancelled` / `provider` / `network`）<br>`retryable?: boolean`（provider/network 为 true）<br>`message?: string`（仅 cancelled 有：`本轮已取消`） | 0 或 1 | **打断语音**。`cancelled` → 进 `cancelled`，把半截文本 + `（已中断）` 入库；其它 → 进 `error`，插入系统消息 **`本轮失败：{reason}`** |
| 14 | `session.resumed` | `resumed_from: string`（Mock 传的是**自己**的 session_id） | 仅重连 | 进 `reconnecting`，气泡显示 persona 的重连台词 |
| 15 | `session.compacted` | `reason: string`（`cancelled`） | 仅取消 | ⚠️ 无处理。⚠️ **语义误用**：`compacted` 本该表示上下文压缩 |

**事件来源 `source`**：只有取消场景的两条是 `renderer`，其余全是 `runtime`
（事件日志面板右侧显示的就是这个值）。

**⚠️ `model.requested` 只发一次，但流式吐字有 6 段** —— 这是 Mock 的简化。
按 v0.4.1 §6.2 的绑定表，`hint` / `reflect` / `end` 绑定到 `render_template`，
**绝不调用模型**，本不该出现流式吐字。详见 `../../shared/contracts/INCONSISTENCIES.md` 第 26 条。

### 1.3 六种典型序列

```text
正常一轮（点「正常回复」/ 回车）—— 约 9~10 秒
  session.started{resumed:false}
  agent.turn.started{input}
  pedagogy.node.entered{Assess}
  pedagogy.decision{next:'Teach',reason:'先确认先验知识'}
  memory.read{query:'recent_mistakes'}
  ── 500ms ──
  model.requested{provider,model}          ← 整轮仅此一次
  model.stream.delta × N                   ← 第 1 段（Assess 文本，累计语义）
  ── 800ms ──  pedagogy.node.exited{Assess} / pedagogy.node.entered{Teach}
  model.stream.delta × N                   ← 第 2 段（Teach，**从空串重新累计**）
  ── 900ms ──  exited{Teach} / entered{Ask}
  model.stream.delta × N                   ← 第 3 段
  ── 900ms ──  exited{Ask} / entered{Hint}
  model.stream.delta × N                   ← 第 4 段
  ── 900ms ──  exited{Hint} / entered{Correct}
  model.stream.delta × N                   ← 第 5 段
  ── 900ms ──  exited{Correct} / entered{UpdateProfile}
  model.stream.delta × N                   ← 第 6 段
  pedagogy.node.exited{UpdateProfile}
  memory.write{dimension,key}
  model.completed{text}                    ← 整轮仅此一次，6 段拼接
  agent.turn.completed{status:'ok'}

取消（点「取消」）
  …（已发出若干 model.stream.delta，可能停在 6 段中的任意一段）…
  agent.failed{reason:'cancelled',message:'本轮已取消'}   ← source='renderer'
  session.compacted{reason:'cancelled'}

报错（点「报错」）
  session.started / agent.turn.started / pedagogy.node.entered{Assess}
  ── 500ms ── model.requested
  ── 700ms ── model.failed{code:'RATE_LIMIT',message:'模型服务限流'}
              agent.failed{reason:'provider',retryable:true}

断线（scenario='reconnect'，⚠️ 界面没有入口，见 1.4）
  session.started / agent.turn.started / pedagogy.node.entered{Assess}
  ── 500ms ── model.failed{code:'CONN_RESET',message:'连接中断'}
              agent.failed{reason:'network',retryable:true}

重连（点「重连」）
  session.resumed{resumed_from}                          ← trace_id 为 null
  ── 900ms ── model.completed{text:'会话已恢复，可以继续。'}   ← 前面没有 delta
              agent.turn.completed{status:'ok'}
```

> ⚠️ **6 段 delta 是各自独立累计的**：第 2 段的第一片是 Teach 文本的第一个字符，
> **不是** Assess 全文 + 1 字符。因为 `App.jsx` 用 `streamRef.current = payload.delta`（覆盖语义），
> 气泡里的文字会**逐段替换**而不是一路增长。接真后端时若按「一段长流」实现，表现会不同。

### 1.4 Mock 的时序与边界细节（排查时要知道）

- `run(text, scenario)` 的 `scenario` 取值：`normal` / `loading` / `error` / `reconnect`。
  **但界面只用到前三个** —— 「重连」按钮走的是另一条通道 `session:reconnect`
  （即 `reconnect()`），所以 `scenario='reconnect'` 这条分支目前**没有界面入口**。
- 「加载中」场景：发出 `model.requested` 后**就此停住**，不发 delta、不发完成。
  状态会一直停在 `loading`，直到用户点「取消」或重新发问。
- 「取消」若在本轮已结束（内部 `traceId` 为 `null`）时调用，**返回 `ok:false` 且不产生任何事件**，
  界面不会有任何变化 —— 这是设计如此，不是故障。
- `Assess` 段的回复文本会带上用户输入的前 **24** 个字（`你问的是「…」`）；
  输入为空时用另一种措辞。其余 5 段是写死的教学文案。
- **6 个教学节点之外的两个节点在演示里走不到**：`Test` 与 `Reflect`。Mock 不发它们。
  要看它们的表现，只能用聊天面板底部那排「**教学动作**」按钮（纯前端置 `node`，**不走事件流**）。
- 一轮的全部**文本**（含末尾那句「以上是 Mock 演示数据」的声明）拼成 `model.completed.text`。
  ⚠️ 那句声明**刻意放在最后一行** —— 放开头会让第一眼看到的是"我答不了"，像坏了（实测反馈）。
- 事件日志面板只保留最近 **200** 条。

> 三个分支实际走不到**。逐帧模式下：
> - 漫游时有摇摆律动（`walk`）✅；
> - 其余情况是**换图**（9 张表情对应 8 个节点 + 状态）＋统一的待机呼吸；
> - 所以**逐帧模式才是能看出教学动作差别的那一个**。

#### RigPet（分层，右键菜单可切）各动作的实际参数

### 3.2 输出 B：语音（`tts.js`）

**双引擎，自动降级**：

```text
speak(text)
  ① 神经语音 edge-tts（经主进程合成，质量高一个数量级，项目本来的选型）
        └─ 失败/不可用/没网/没装 Python → 降到 ②
  ② Chromium 内置 Web Speech API（系统语音，零依赖、零密钥、零网络）
        └─ 环境不支持 → 回调 'unsupported'
```

**兜底不是可选项**：对方机器上可能没装 Python、没装 edge-tts、或者没网 ——
那种情况下桌宠必须还能说话，只是音色差一点，**不能干脆哑掉**。

导出函数：

| 函数 | 签名 | 说明 |
| --- | --- | --- |
| `ttsSupported()` | `() => boolean` | 系统语音是否可用 |
| `speak(text, onState)` | `(string, (s:'start'\|'end'\|'error'\|'unsupported') => void) => Promise<void>` | **先打断正在念的内容**再开始；念的是完整回复，不是流式片段 |
| `stop()` | `() => void` | 立即停止（可中断播放的核心）。⚠️ **两个引擎都停** —— 神经语音走 `<audio>`、系统语音走 `speechSynthesis`，只停一个的话另一个会继续念 |
| `pause()` / `resume()` | `() => void` | 暂停 / 继续（Chromium 有 pause→resume 卡住的已知问题，UI 上以「停止」为主操作） |
| `isSpeaking()` / `isPaused()` | `() => boolean` | 当前状态（`App.jsx` 未使用，自己维护 `speaking`/`paused`） |
| `engineName()` | `() => string \| null` | 上一次实际用的引擎（`'edge-tts'` 或 null=系统语音） |
| `voiceReport()` | `() => Promise<{supported,total,zh,picked}>` | 诊断用：列出可用中文音色 |

实现细节：

- **神经语音**：合成在主进程（`tts:synthesize`，返回 `data:audio/mpeg;base64,...`），
  渲染端 `new Audio(...)` 播放。**合成结果带 24 条 LRU 缓存** —— 同一句反复念不用重新合成。
  超过 600 字会被主进程截断。
- **系统语音**：音色优先挑 `Yaoyao > Xiaoxiao > Huihui`（顺序是**语调的一部分**，别随便改；
  Kangkang 男声与角色形象不符，不用）；`rate = 0.98`、`pitch = 1.05`；
  **按句子切块，每块 ≤60 字**（绕开 Chromium 长文本约 15 秒被静默截断的问题，也让「停止」更跟手）；
  **句间插 170ms 停顿**（`SPEECH_STYLE.gapMs`）—— 这是「听起来像人在说话」最关键的一项，比换音色还管用。
- 内部用 `generation` 计数识别「被自己打断的回调」，避免旧回调把「正在朗读」状态改错。

**自动打断的 5 个时机**（任务书验收项「可中断播放」的落地）：

1. 用户点「取消」→ `doCancel()` 先本地 `stop()`，再调 IPC；
2. 收到 `agent.failed`（取消 / 出错）→ 回调里 `stop()`；
3. 新一轮开始（`session.started` / `agent.turn.started`）→ `stop()`，避免新旧语音重叠；
4. 手动：语音条的「停止朗读」按钮、关掉「🔊 自动朗读」开关；
5. 组件卸载（退出桌宠）→ `useEffect` 清理里 `stop()`。

> ⚠️ 一轮只念**一次** —— `model.completed` 整轮只发一次，携带 6 段拼接后的全文。
> 中间节点只发 delta，**不发 completed**，这样语音不会被打断成碎片。

### 3.3 输出 C：窗口行为

| 行为 | 细节 |
| --- | --- |
| 窗口属性 | 无边框、透明、不可缩放/最大化/全屏、无阴影、置顶（层级 `screen-saver`） |
| 默认尺寸与位置 | **220×420**，屏幕工作区右下角（距右边 24px、底边 24px） |
| 尺寸为什么是 420 | 角色 300 + 顶部**固定预留 120** 给气泡。气泡锚在窗口顶部、角色锚在底部，若窗口高度刚好等于角色高度，气泡只能盖在角色头上（实测挡住额头）；而让窗口「气泡出现时临时长高」会导致拖动时窗口/气泡/角色互相追（出现「气泡越拖离人物越远」，更糟）。所以固定预留，窗口一动不动 |
| 聊天面板展开 | **380×620**；展开时 `nx = min(x, 工作区右边−380)`、`ny = max(工作区顶, y−200)` 保证不越界 |
| 聊天面板收起 | 回到 220×420，`y` 加 200 让**底边不动**（角色不会跳位置） |
| 拖动 | 渲染进程按 `screenX/screenY` 增量调 `win:move-by`；**8px 阈值**区分「点击」与「拖拽」 |
| 拖动期间 | 漫游暂停；松手后**恢复到拖动前的值**（不是无脑打开） |
| 自动漫游 | 每 **9 秒**判断一次；挑屏幕内随机落点（纵向贴任务栏上沿）；分帧 16ms/步、耗时 1200~2600ms、缓动 `easeInOutSine`；**聊天面板打开时不走**；转向时通知渲染进程翻面 |
| 漫游默认状态 | **关闭**（主进程与渲染进程两边都是 false，已一致）。⚠️ 漫游关闭时，右键菜单的「随便走走」**点了没反应**（`wanderOnce()` 会直接 return） |
| 位置夹取 | 所有移动都走 `safeSetPosition()`，**强制夹在屏幕工作区内**（防止小人跑丢）。⚠️ 内部用 `setBounds` 显式带尺寸，不是 `setPosition` —— Windows 分数 DPI 下只调 `setPosition` 窗口会只增不减地漂 |
| **点击穿透** | **主进程每 50ms 轮询决策**：`screen.getCursorScreenPoint()` 拿光标位置 → 换算到窗口坐标 → 查渲染端上报的**矩形 + 64×64 alpha 掩码** → 决定是否 `setIgnoreMouseEvents`。渲染端只负责**上报命中区**（`win:set-hit-region`，启动发一次 + 每 300ms 重发）与**上报 UI 是否展开**（`win:set-ui-open`） |
| 穿透的优先级 | `forceThrough`（用户手动）> `uiOpen`（菜单/面板展开 → 不穿透）> 光标是否在角色身上 |
| 托盘的「退出」 | ✅ **托盘菜单第一项就是「退出」**，之后才是分隔线 / 显示隐藏 / 归位 / 自动溜达。托盘是唯一在任何状态下都能退出的入口 |
| **关窗口 = 隐藏** | ✅ 点窗口关闭只**隐藏**，不退出（`win.on('close')` 里 `preventDefault + hide`）。这样误关窗口不会丢桌宠。退出只能走托盘第一项 / 右键菜单「退出」/ `Ctrl+Alt+Shift+X` |
| 托盘图标 | 角色自己的脸（base64 内嵌，避免打包后路径失效）。⚠️ 曾用 1×1 透明图占位，结果托盘里根本看不见、用户既找不到人也没法退出 |
| 全局快捷键 | `Ctrl+Alt+Shift+D` 归位、`Ctrl+Alt+Shift+X` 退出（被占用时不影响托盘使用） |

> **穿透为什么改成主进程轮询（重要）**
> 原方案是渲染进程 `setIgnoreMouseEvents(true, {forward:true})`，指望系统把 `mousemove`
> 转发进页面再按命中与否切换。但这个转发**在部分机器上根本不生效**（本机实测就不行）——
> 渲染端永远收不到鼠标移动，于是：① 点空白处的穿透失效（桌宠一直挡着后面的图标）；
> ② 更糟的是角色变成点不动，只能靠看门狗整体关掉自动穿透。
> 改成主进程主动问系统光标位置，**不依赖任何转发，所以一定可用**。
>
> ⚠️ 旧方案配套的「3 秒看门狗」**已随旧方案一起删除**。现在没有看门狗，因为轮询方案不依赖转发。

> ✅ **已修复（核对于 2026-09-19）**：`App.jsx` 的 `toggleThrough()` 现在按 `next` 传参
> （`setIgnoreMouse(next)`），强制穿透**可以开、也可以关**。
> 历史上这里是一条待修的一行缺陷 —— 无论开还是关都传 `true`，而且只能从右键菜单进入
> （进去就把菜单关掉），所以一旦开启强制穿透，只能重启应用（`INCONSISTENCIES.md` 第 30 条）。
> 保留这段是因为那条契约条目还停在旧状态上，**以代码为准**。

### 3.4 输出 D：本地状态（`petStats.js`，好感度 / 心情 / 精力）

存储位置：`localStorage`，键 `deepprof.petStats.v1`（**纯本地，默认不外发**）。

| 字段 | 初始值 | 说明 |
| --- | --- | --- |
| `affinity` | 4 | 好感度（0~100）。初始不是 0，否则「刚认识」阶段太长看不到变化 |
| `mood` | 72 | 心情（0~100） |
| `energy` | 85 | 精力（0~100） |
| `asleep` | false | 精力 ≤12 时自动入睡；睡到 ≥96 自动醒 |
| `consent` | **false** | 数据授权开关。**默认关闭时一个字节都不会离开本机** |
| `counts` | `{pat:0,tap:0,chat:0}` | 互动次数 |
| `lastSeen` / `born` | 当前时间 | 用于按「实际流逝时间」结算衰减 |

衰减/恢复速率（**每小时**，`RATE` 表）：心情 −6、精力 −9、睡着时精力 +26、好感度 −0.4；
**离线时段一并结算，但封顶 12 小时**（免得关几天回来角色「废了」）。

每次互动加成（`GAIN` 表）：摸头 `{affinity+1, mood+4, energy−1}`、
普通点击 `{+0.3, +1.5, −0.5}`、完成一轮对话 `{+2, +3, −2}`。

好感度阶段（`STAGES`）：`stranger` ≥0「刚认识」、`familiar` ≥20「熟悉」、
`close` ≥50「亲近」、`attached` ≥80「依赖」。
**这是好感度被用户直接感知到的地方** —— `persona.js` 的摸头台词按这四个阶段换语气。

**授权面板已经做了**：聊天面板底部的「未授权上报 / ⚠ 已授权上报」按钮可以展开一个 `consent-box`，
里面能预览 `exportForDataTeam()` 的 JSON、能撤回授权、能清空记录。
文案明确写着「下面的数据**默认不出本机**，开关不开就一个字节也不发」「里面只有互动次数和状态值，
**不含任何对话内容**」。

> ⚠️ 但 `exportForDataTeam(s)`（仅 `consent === true` 时返回摘要对象）**目前仍然没有任何调用方** ——
> **偏好上报通道还没有**。所以这份 schema 仍是一条断头路：UI 齐了、字段登记了，只差一条 IPC + 一个后端端点。
>
> ⚠️ `STAGES` / `GAIN` / `RATE` 三组是**硬编码的体验参数**。只要后端将来也参与好感度计算，
> 这三组值就必须双方一致，否则同一句「你答对了」两边算出的增量不同。

### 3.5 输出 E：preload 暴露的完整 API（`window.deepprof`）

```js
// ── tts 下 2 个 ──
tts.synthesize(text: string)                 -> Promise<{ok, engine?, audio?, reason?}>  // tts:synthesize
tts.selftest()                               -> Promise<{ok, detail?, reason?}>          // tts:selftest
```

两条推送通道：

- `runtime:event` —— 完整事件对象（envelope + payload），**渲染进程唯一的事件入口**；
- `pet:walk` —— `{ walking: boolean, dir: 1 | -1 }`，由主进程漫游逻辑直接发出。
  ⚠️ **它不是 Runtime 事件**，不经过 `runtime:event`，后端不要生产它。
  （`preload/index.js` 里形参名写作 `walking`，实际收到的是对象；`App.jsx` 写了对象/布尔
  双兼容分支，属历史遗留。）

**明确不暴露**：裸 `ipcRenderer`、任何模型密钥或 Provider 配置、文件系统
（含 TTS 的临时文件 —— 渲染端只拿到 base64 音频）、任意通道名的动态 IPC、指定 provider/model 的直接入口。
