# desktop/tools —— 桌宠模块的工具箱

> 给接手的人：这里的脚本**都不是运行时依赖**，只在「做素材 / 验证 / 发布」时手动跑。
> 桌宠本身跑起来只需要 `desktop/` 下的 `src/` 和 `package.json`。

| 目录 / 文件 | 干什么 | 怎么跑 |
| --- | --- | --- |
| `素材流水线/` | **把美术出的原图变成能播的帧**：拆三格表情、归一化对齐、合成眨眼帧、拆分层 rig | 见下面的「⚠️ 跑法」 |
| `素材流水线/生成应用图标.py` | 从立绘裁脸生成 **`build/icon.ico`**（exe / 任务栏 / 快捷方式的应用图标，7 档尺寸）。**换角色或换姿势后要重跑**，然后 `git add -f desktop/build/icon.ico`（为什么必须 -f 见脚本头部） | `python desktop/tools/素材流水线/生成应用图标.py`（**这条在哪跑都行**，见下方例外） |
| `实拍驱动.mjs` | **程序化驱动桌宠做实测**（开面板、点教学节点、高频录屏抓眨眼）。桌宠是置顶透明窗口，从外面点鼠标要赌坐标，走 CDP 直接 `element.click()` 稳得多 | 见 `实拍驱动.mjs` 文件头 |
| `发布release.js` | 打好的安装包发到 GitHub Release（`release/` 是 gitignore 的，**exe 不随分支走**） | `node 发布release.js` |
| `bench/` | 性能实测探针（由 `DEEPPROF_BENCH_OUT` 环境变量启用，平时完全不参与运行） | 见 `src/main/index.js` 顶部那段注释 |
| `tts/` | 语音朗读用的 `say.py` | 主进程按需调用 |

## ⚠️ 素材流水线的跑法（**这里有个坑，务必先读**）

`素材流水线/` 里的脚本**是相对"自己所在目录"找数据的**（`HERE = dirname(abspath(__file__))`，
然后 `动作帧/ = HERE/动作帧`）。而真正的素材在 **`_素材工作区/动作帧/`**。

所以：

> 例外：`生成应用图标.py` **不吃这一套** —— 它按 `__file__` 推项目根，输入输出都是
> `desktop/` 下的固定路径，**在哪跑结果都一样**，也不需要 `_素材工作区/`。

- **要在 `_素材工作区/` 下跑**，用的是**那一份**脚本副本：
  ```
  cd <项目根>/_素材工作区
  python 归一化帧.py 表情
  ```
- ⚠️ **直接在 `desktop/tools/素材流水线/` 下跑会静默失败** ——
  它会去找 `desktop/tools/素材流水线/动作帧/原始/`（那个目录不存在），
  只打印一句「原始目录是空的」就退出，**退出码还是 0**。
  2026-09-20 晚有两条流水线都踩了这一脚。

### 两处副本的关系

`_素材工作区/` 与 `desktop/tools/素材流水线/` **各有一份脚本**，
因为 `_素材工作区/` 是 git 排除的（不进交付），必须在这儿留一份能跑的。
两份**内容要手动保持一致** —— 目前 `归一化帧.py` / `眨眼合成.py` / `裁四格.py` /
`三格表情拆分.py` 是一致的，但**`预览.py` 与 `拆腿.py` 已经分叉**（`tools/` 那份是 09-20 14:36 的新版，
`_素材工作区/` 那份还停在 09-19）—— 跑到哪一份结果不一样，动手前先 diff 一下。

> 📌 治本的办法是让脚本按环境变量或参数找数据根，而不是按 `__file__`。
> 本轮没做（怕动到别的动作），先把这个坑记在这。
