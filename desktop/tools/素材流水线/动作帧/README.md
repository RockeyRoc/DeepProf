# 动作帧工作区

> 桌宠「从贴纸变成活人」的地方。路径：`DeepProf/_素材工作区/动作帧/`

---

## 一、三步走

```
① 出图    即梦生成 → 丢进  原始/<动作名>/        （命名 walk_0.png、walk_1.png …）
② 归一化  python 归一化帧.py <动作名>            → 归一化/<动作名>/
③ 预览    python 预览.py <动作名>                → 预览/   ← 必须看！不看别接
```

不想敲命令就**双击** `_素材工作区/做动作帧.bat`（不填参数=处理全部动作）。

看预览满意了，加 `--接入` 直接拷进桌宠素材目录：

```
python 归一化帧.py walk --接入
```

---

## 二、⚠️ 出图前必读：走路帧必须是侧视

**这是我们踩过的第一个坑，不写下来一定会再踩。**

现在的角色立绘（`原创桌宠形象.png`）是**正面站姿**。但桌宠走路 = 窗口在屏幕上**左右横移**。
正面视角下，人走路时腿是往**屏幕里外**摆的 —— 横移时你几乎看不出腿在动，**4 帧也救不回来**，
仍然像贴纸在滑。

所以走路帧要出**侧视 / 3-4 侧视，朝向画面右侧**。朝左走不用另外出图 ——
播放器已经有水平翻转（`FramePet.jsx` 里 `dir` 参数），同一套帧翻过来就是朝左。

| 动作 | 视角 | 理由 |
| --- | --- | --- |
| **walk（走路）** | **侧视朝右** | 腿的前后摆动一眼可见 |
| idle / talk / think / sad / happy / tap | 正面即可 | 不涉及横移，正面更有亲和力 |

---

## 三、出图 Prompt

### 3.1 走路帧（侧视朝右）

**推荐做法：一次生成"四格连续动作图"，再裁开。**
理由：AI 逐张生成时，四张之间角色大小、比例、画风都会飘；同一张画布内生成，
比例和步态连续性是**天然对齐**的。这是参考项目 `dsh-dfy` 的 `SOURCE.md` 记下的做法。

```
以参考图中的角色为准，严格保持相同的画风、配色、服装与发型。
Q版日系二次元拟人化蓝鲸少女，全身侧视图，朝向画面右侧，
四格连续走路动作分解图，从左到右依次为走路循环的四个关键帧：

第1格：左腿向前迈出，右腿在后，双臂自然前后摆动，身体微微前倾
第2格：双脚并拢，身体直立，双臂自然下垂（过渡帧）
第3格：右腿向前迈出，左腿在后，双臂自然前后摆动，身体微微前倾
第4格：双脚并拢，身体直立，双臂自然下垂（过渡帧）

深蓝色双马尾随动作轻微摆动，耳侧一对鲸鱼胸鳍，身后一条短小的鲸鱼尾。
学院风：白色衬衫 + 浅蓝色针织开衫 + 深蓝色百褶短裙 + 白色过膝袜 + 深蓝色小皮鞋。
腿部完整可见，约2.5头身，赛璐璐上色，干净线条，柔和阴影，冷色调。
纯白背景，四个角色等距排列，每个角色四周留足空白，不要互相遮挡、不要裁到角色。
--no 文字, 水印, 签名, 长裙, 女仆装
```

拿到四格图后，横向裁成 4 张，命名 `walk_0.png` ~ `walk_3.png`。

> 裁图不用自己动手：把四格图直接丢进 `原始/walk/`，跑 `python 裁四格.py walk` 会自动切开。

### 3.2 逐张生成（备选）

四格图效果不好的话，退回逐张生成。**每张都要传同一张参考图**，并且固定种子（如果即梦支持）：

```
（上面 prompt 的公共部分）+ 走路动作第 N 帧：<该帧描述>
```

逐张生成时**务必**让角色大小和位置尽量一致 —— 归一化脚本只能对齐，不能修复
"这一帧角色画大了 20%"这种问题。脚本会检测并警告（见下）。

## 四、目录

| 目录 | 放什么 | 谁写 |
| --- | --- | --- |
| `原始/<动作>/` | 即梦导出的原图，命名 `<动作>_0.png` 起 | **你** |
| `归一化/<动作>/` | 脚本输出，统一画布、对齐好的帧 | 脚本 |
| `归一化/_规格.json` | 画布尺寸/角色高度/脚底线 —— **所有动作共用** | 脚本 |
| `预览/` | 拼版图、GIF 动图、检测调试图 | 脚本 |
| `rig/` | 单图拆分层的结果（另一条技术路线，见第五节） | 脚本 |

> ⚠️ `_规格.json` 是**全局**的：所有动作必须共用同一套规格，否则切动作时角色会忽然变大变小。
> 一旦开始出正式素材就不要再改它。要改就全部重跑一遍归一化。

## 五、另一条路线：单图分层 rig（**已接入桌宠**）

除了逐帧，还有一条路：把**一张**立绘拆成「身体 / 左腿 / 右腿」三层，
用代码让腿绕髋点摆动 —— 不需要 AI 再出图，零一致性风险。

```
python 拆腿.py            拆  desktop/.../assets/pet/idle.png → 动作帧/rig/
python 拆腿.py --接入     顺便拷进桌宠工程
python 预览rig.py         在 Python 里把走路演出来 + 两条硬校验
```

**两条路在桌宠里是并存的**，右键菜单「换成逐帧动作 / 换成分层走路」现场切换对比。
渲染代码：`desktop/src/renderer/src/RigPet.jsx`（分层）和 `FramePet.jsx`（逐帧）。

### 5.1 拆腿做了哪些判断

| 判断 | 怎么做的 |
| --- | --- |
| 裙摆线在哪 | 找最后一个「整行藏青像素数 ≥25」的行（百褶裙有深色缝，不能用最长连续段） |
| 两腿怎么分 | 两腿在裙摆以下是**粘连**的，连通域分不开 → 在下方已分开处量出分界线，往上沿用 |
| 鲸尾怎么办 | 尾巴紧贴右腿，按下方干净区域量出的右边界切开，尾巴留给身体层 |
| 波浪裙摆 | 裙摆线附近额外按**颜色**排除藏青像素，免得啃掉裙子下缘 |
| 转起来露缝 | 身体层多保留大腿顶部 14px（inset）盖住旋转缝 |

### 5.2 两条硬校验（`预览rig.py` 自动跑）

1. **零角度必须逐像素还原原图** —— 层只要错位一像素或 z 序排反，这里就炸
2. **延长区必须被身体完全盖住** —— 否则转起来会看到凭空冒出的肉色方块

> 校验 1 有且只有一处豁免：两层**故意重叠**区里的抗锯齿半透明边缘像素
> （叠加公式 `a + a(1-a)` 会让它比原图略实一点点，肉眼不可见）。
> 豁免条件按问题本质写（两层都有贡献 + 原图是半透明边缘），所以**掩盖不了真的错位**。

### 5.3 踩过的坑

| 坑 | 原因 | 解法 |
| --- | --- | --- |
| 旋转后轮廓有一圈黑边 | 透明像素的 RGB 是 (0,0,0)，插值把黑色混进边缘。PIL 和 Pixi 的 GPU 过滤都会 | **颜色外扩**（bleed）并**烘进导出的 PNG**，不能只在预览里做 |
| 角色只显示下半身 | 挂载时 `.pet-host` 还没量出尺寸，`fit()` 提前返回把 scale 留成 1 | 缩放在 ticker 里**每帧重算**，别存起来 |
| 启动瞬间自截图是空的 | 那一刻 Pixi 贴图还在异步加载 | 延时 2.5 秒再抓一张（`deepprof-window-2s.png`） |
| 抓不到走路那一刻 | 桌宠是"溜达"的 | 设 `DEEPPROF_SNAP=1` 再启动，每 2 秒连拍 10 张 |

## 六、怎么读归一化的警告

脚本会主动喊，别忽略：

| 警告 | 意思 | 怎么办 |
| --- | --- | --- |
| `帧间高度差 >10%` | 各帧角色大小/姿态差太多 | 重出图。正常走路起伏应在 5% 以内 |
| `各帧头部水平位置相差 …px` | 各帧角色左右位置飘了 | 轻微可接受，>4% 画布宽建议重出 |
| `<帧> 超出画布` | 角色被裁了 | 调大 `--target` 或画布尺寸后重跑 |
| `整张都是透明的` | 抠图抠穿了（白衬衫白袜子被当背景） | 该图背景不干净，重出或手动抠 |

## 七、脚本做了什么（放心用，但别乱改）

`归一化帧.py` 四件事：

1. **去背景** —— 用连通域找「和画布边缘连通的浅色区域」，所以角色身上的白色
   （衬衫、过膝袜）**不会被误抠**。顺带做**白底去污染**：边缘像素是角色色和白底混出来的，
   按 `前景 = (观测 - (1-a)·白) / a` 反解，消掉灰白毛边。已经是透明 PNG 则跳过这步。
2. **统一缩放系数** —— 关键：**不是**逐帧缩放到同一高度。逐帧缩放会把走路时自然的
   上下起伏抹平，人就变纸片了。用一个系数、保留帧间真实的尺寸差。
3. **水平按「头部中心」对齐** —— **不是**按外接矩形中心。走路时腿在前后伸，
   外接矩形宽度一直在变，按它对齐角色会左右抖。头是走路时最稳的锚点。
4. **脚底对齐同一基线**。

`预览.py` 生成拼版图（画脚底红线和中心蓝线）和棋盘格底的 GIF。

## 八、验收标准

接进桌宠之前，`预览/<动作>_拼版.png` 必须满足：

- [ ] 所有帧的脚底**都踩在红线**上
- [ ] 所有帧的头**都落在蓝虚线**上
- [ ] 帧与帧之间角色**没有忽然变大变小**
- [ ] 棋盘格上**没有白边/灰边**残留
- [ ] 动图看起来**像在走路**，而不是在抽搐

再看 `预览/<动作>_<帧率>fps.gif`，确认**循环接得上**（最后一帧接第一帧不跳）。
