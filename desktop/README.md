## 一、这是什么

Electron + React + PixiJS 写的**桌面桌宠**，是 DeepProf 交互层（DESIGNv0.4.1 §4.1）
第一个能跑起来的模块，对应 §16.4 张钧翔的任务书。

一句话概括它的职责：**把 Runtime 吐出的事件流翻译成一个看得见、听得着、能摸的小人。**

### 定位说明（不吹牛的部分）

- 计划书 §3.3 把桌宠定位为「**核心学习流程完成后的交互完善**」。本模块**不产生**任何
  教学内容、不做检索、不调模型 —— 所有回复文本都来自主进程里的 **Mock**。
- 因此本轮**不声称桌宠带来任何学习提升**。它的价值是：把「事件 → 表现」这条链路
  **先跑通并可视化**，让后端联调时有一个真实可用的消费端。
- 当前处于 §16.8 的**阶段 02「独立最小模块」**：桌面端能独立跑通，集成门槛要求的三份
  文档（启动说明 / 输入输出 / 失败样例）在 `docs/` 下。
- 界面上的「回复」不是真回答。`src/main/index.js` 的 `SCRIPT` 常量里是几段写死的教学
  用语，只有 `Assess` 一段会带上用户输入的前 24 个字，免得看起来像程序坏了。
  末尾那句「以上是 Mock 演示数据」**刻意放在最后一行** —— 放开头会让第一眼看到的是
  「我答不了」，像坏了（实测反馈）。

## 二、怎么跑起来

**最简单**：双击 `启动桌宠.bat`（内部就是 `npm run dev`，并把退出提示打在窗口里）。

```bat
:: 等价于
npm run dev
```

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 开发模式，`electron-vite dev`，改代码热更新 |
| `npm run build` | 编译到 `out/`（main / preload / renderer 三份产物） |
| `npm run start` | `electron-vite preview`，**直接跑 `out/` 里的旧产物，不会重新编译** |

启动后会发生什么：

1. 屏幕**右下角**出现一个小人（**220×420** 的无边框透明窗口），只有角色、没有面板。
2. 终端打印 `[桌宠] 窗口已显示 @ (x, y) 220x420`、`[桌宠] 渲染诊断: {...}`、
   `[桌宠] 快捷键 ... ✅/❌`。
3. 会在 `%TEMP%` 下写两张窗口自截图（`deepprof-window.png` / `-2s.png`）。
4. ⚠️ 终端还会有两类**临时诊断日志**在刷（`[窗口诊断] resize` 与 `[气泡诊断]`），
   是排查用的，不是故障。

**退出方式（5 种，任意一种）**：托盘图标右键**第一项「退出」**、右键菜单「退出」、
快捷键 `Ctrl+Alt+Shift+X`、关掉那个黑窗口。

> ⚠️ **点桌宠窗口的关闭按钮不退出，只是隐藏** —— 这是刻意的，避免误关丢桌宠。

**找不到小人时**：按 `Ctrl+Alt+Shift+D` 归位，或右键菜单「回到原位」。

> 环境要求、打包、失败排查见 **[`docs/启动说明.md`](docs/启动说明.md)**。

## 四、模块边界：吃什么、吐什么

```text
        （后端未实现）              主进程（现在）                渲染进程
   FastAPI Runtime  ──事件──▶  MockRuntime  ──IPC──▶  preload  ──▶  App.handleEvent
                                  ②        runtime:event   ③        ④（先去重）
                                                            │
                                            画面（Pixi）/ 语音（TTS）/ 窗口行为
```

- **输入**：统一事件流（15 种事件，envelope **8 个**公共字段）。
  渲染进程的**唯一**事件入口是 `runtime:event` 一条通道 ——
  这是 §4.4「UI 不直连 Tool、Memory 或 Provider」的落地。
- **输入（反向）**：渲染进程只发 3 条会话请求 + 11 条纯本地窗口控制 + 2 条语音合成。
- **输出**：像素（动画/表情）、声音（TTS）、窗口行为（移动/穿透/变形）、
  本地偏好（localStorage 里的好感度等，**默认不对外发送**）。

字段级的完整清单见 **[`docs/输入输出.md`](docs/输入输出.md)**。

## 五、关键设计决策

| # | 决策 | 为什么这么做 |
| --- | --- | --- |
| 1 | **Mock Runtime 放在主进程**，不拆文件 | 按 §7.2，真实事件由后端产生、渲染层只负责消费。放主进程后，将来换真后端**渲染层一行都不用改**。不拆文件是因为 electron-vite 会把主进程里相对路径的 `require` 留成外部依赖，拆出去运行时就是 `Cannot find module`。 |
| 2 | **preload 只暴露白名单**，绝不交出裸 `ipcRenderer` | §16.4 验收项「渲染进程不持有模型密钥」。`contextIsolation: true` + `nodeIntegration: false`，将来真实模型调用只在主进程发生。 |
| 3 | **窗口就是角色的身体**：漫游 = 主进程移动窗口 | 桌宠要在桌面上「走」，而不是在窗口里走。分帧小步移动（16ms/步）+ `easeInOutSine`，一次 `setPosition` 会看起来像瞬移。 |
| 4 | **所有移动都强制夹取在屏幕工作区内**（`safeSetPosition`） | 踩过的坑：曾有版本不做夹取，窗口飘到屏幕外（y 变成负数），用户既看不到也点不到。配套还有托盘菜单和两个全局快捷键作为「找回来」的兜底。⚠️ 内部用 `setBounds` **显式带尺寸**而不是 `setPosition` —— Windows 分数 DPI 下只调位置窗口会只增不减地漂。 |
| 5 | **点击穿透由主进程每 50ms 轮询决策**（`startThroughWatch`） | 原方案靠系统把 `mousemove` 转发进渲染进程，但**在部分机器上根本不生效**（本机实测就不行）：穿透失效 + 角色点不动。改成主进程主动问 `screen.getCursorScreenPoint()`，**不依赖任何转发，所以一定可用**。命中区由渲染端上报（矩形 + 64×64 alpha 掩码，`win:set-hit-region`）。 |
| 6 | **事件按 `event_id` + `sequence` 双重去重** | §16.4 验收项「断线重连不重复展示」需要它。两张网都留着，因为真后端可能只保证其中之一。 |
| 7 | **两套 PNG 播放器并存**，右键菜单现场切换 | `FramePet`（逐帧换图，**默认**）能显示 9 张表情（9 个教学槽位**一一对应、0 复用**），是教学动作映射的载体；`RigPet`（一张立绘拆三层、腿由代码摆）零素材一致性风险，额外提供走路。哪条好用用哪条，不押注。 |
| 8 | **TTS 双引擎**：神经语音为主、系统语音兜底 | 神经语音（edge-tts）音质高一个数量级，是项目本来的选型；但它要 Python + 联网。**对方机器上没装 Python、没装 edge-tts、或者没网，桌宠都必须还能说话** —— 兜底不是可选项。`stop()` 会同时停掉两个引擎。 |
| 9 | **一切由事件驱动，状态单一来源** | 连「用户点了取消」也是：前端先本地停语音，再调 `session:cancel`，等 `agent.failed {reason:'cancelled'}` 事件回来才切状态。多一次 IPC 往返，换来状态不会两处打架。 |
| 10 | **可见的退出口必须可靠** | 托盘图标曾用 1×1 透明图占位，结果托盘里看不见、用户既找不到人也没法退出。现在托盘用角色自己的脸（base64 内嵌），**且菜单第一项就是「退出」**；另加两个全局快捷键作为紧急出口。 |
| 11 | **台词全部收敛在 `persona.js`** | 之前台词散落在 `App.jsx`、`main/index.js`、`RigPet.jsx` 里，且大多写成"系统状态提示"而不是"人在说话"（「思考中…」「出错了，可以重试」）。改一次语气要翻五六个文件，所以一直没人改。收敛之后想调语气只改一个文件。 |

## 六、已实现 / 未实现（截至快照时间）

### 已经实现的

- 桌面壳：无边框 / 透明 / 置顶 / 不可缩放；拖动、单击、右键菜单、托盘、全局快捷键。
  **关窗口 = 隐藏**（不退出），**托盘第一项 = 退出**。
- 自动漫游：主进程挑选屏幕内落点、分帧走过去、转向时角色翻面、聊天面板打开时不动、拖动时暂停。
- **点击穿透（主进程轮询式）**：50ms 判断一次光标是否压在角色的 alpha 掩码上，
  菜单/面板展开时不穿透，另有右键「点击穿透」手动开关。
- **五状态 Mock 事件流**：正常回复 / 加载中 / 报错 / 取消 / 重连，配一个可展开的「事件日志」面板。
- **一轮走完 6 个教学节点**（Assess→Teach→Ask→Hint→Correct→UpdateProfile），
  每个节点有 800~900ms 停留 + 独立的逐字流式文本，让「教学动作 → 表情」的映射在演示里真的看得见。
- 流式文本渲染（`model.stream.delta` 为**累计全文**语义），气泡 + 闪烁光标。
- **事件去重**：`event_id` + `sequence` 双重，支撑「断线重连不重复展示」。
- 语音：神经语音（edge-tts）为主、系统合成音兜底；自动朗读、暂停 / 继续、停止朗读、
  朗读最新回复；**五种时机自动打断**；合成结果带 LRU 缓存。
- 教学节点 → 动作映射（**8 个节点**，含 `Reflect`）+ 运行状态映射 + 优先级链
  （走路 > 状态 > 教学节点 > 待机）。`Teach` / `Ask` / `Hint` / `Correct` 各有独立动作。
- 两套 PNG 播放器 + Live2D 播放器（`Live2DPet.jsx`）。
